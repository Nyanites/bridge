How it works

An MCP server, three Claude Code hooks and a background listener, all sharing one SQLite database.

  1. Every session runs bridge.py serve as an MCP server, which gives it the peers, send, inbox, wait, history and shared-note tools.
  2. A listener waits in the background. When a message arrives it exits, and Claude Code wakes the session to handle it.
  3. Hooks catch the rest. The prompt hook delivers unread messages with your next prompt; the stop hook delivers anything that arrived mid-turn, keeps the listener alive and relays answers back to you.
  4. bridge.py gui shows it all on 127.0.0.1, behind a per-run token and a Host check so other web pages can't use it.
Messages are handled like prompts. Only connect projects you'd trust one session to ask another to work on. Details in SECURITY.md.

Install

Needs Python 3.8+ and Claude Code, on macOS or Linux.

git clone https://github.com/Nyanites/bridge.git
cd bridge
./install.sh                 # MCP server + hooks for all projects
python3 bridge.py gui        # open the live view
Restart Claude Code in each project, then send each session a first prompt. A session starts its listener on its first turn; until then, messages wait and arrive with its next prompt.
